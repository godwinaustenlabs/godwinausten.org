# 0005 — A generated placeholder film, so the transport is live before the cut is

**Date:** 2026-09-03
**Status:** accepted
**Amends:** [0003 — Generated placeholder artwork](0003-no-third-party-imagery-shipped.md)

## Context

`MEDIA_ASSETS.vsl` shipped with `fallback: null` on the reasoning recorded in
ADR 0003: there is no encoder on the build machine, and a stock clip would put
someone else's footage on the page. With nothing to play, `vsl-panel` ran the
drawn `PlaceholderReel` instead — a good picture, and honest about being one.

What that missed is that the VSL panel is not a picture. It is the only
control-heavy component in the funnel: play/pause, ±5s, a scrubber, an elapsed
clock, and sound, all of it hand-built because the browser's own control bar is
another vendor's design language. `FilmFrame` disables the whole transport when
`src` is absent — correctly, since buttons that look live and do nothing are
worse than buttons that say they are waiting. So every control on it had been
shipped, reviewed and never once operated, and no test could reach them.

Two bugs were sitting behind that, both invisible until something played:

- `/api/media/[id]` ignored `Range` on the fallback path while still sending
  `Accept-Ranges: bytes`. A player that cannot ask for a byte range cannot seek.
- The scrubber's hit target was the four pixels of the hairline it draws.

The owner asked for a real film in the slot.

## Decision

Generate one, and keep it in the repo's own visual language.

`scripts/generate-placeholder-video.mjs` (`npm run gen:placeholder-video`) draws
the frames on a canvas and encodes them to H.264/MP4 — 1280×720, 25fps, 20
seconds, about 500 KB — writing `public/assets/film-placeholder.mp4`. It is the `fallback` for both video
assets — the VSL and the case-study reel — so the media route serves it until the
owner puts an object at the real key, at which point the real cut takes over with
no deploy and nothing else changed. One file covers both slots: it says it is a
placeholder across every frame, so a second cut saying the same thing again would
only be another half-megabyte.

**The encoder is one already in the repo.** Playwright is a devDependency for
the e2e suite, and its bundled Chromium supports `video/mp4;codecs=avc1` in
`MediaRecorder`. A canvas feeds `captureStream()`, Chromium encodes, and the
bytes come back over the CDP bridge. No ffmpeg, no wasm codec, no new package —
which matters because §4.3 makes a dependency a decision for the owner.

**It burns in a timecode.** The film is a stand-in and an instrument: the clock
on the picture has to agree with the clock under the transport, so scrubbing and
±5s can be seen to work rather than assumed to. Two e2e tests in
`tests/e2e/home.spec.ts` now drive the whole transport, which is only possible
because there is something in the slot.

ADR 0003 is amended, not overturned: nothing shipped here is sourced from
anywhere. Every visual asset on this site is still generated by a script in this
repository.

## Consequences

**Easier.** The funnel's last step works end to end today, the transport is
exercised on every CI run, and the two bugs above are fixed and covered. Anyone
reviewing the player can operate it.

**Harder.** `public/assets/` gains 500 KB. It is served only from the media
route, never on first paint, and it is the one asset a visitor has explicitly
asked for by clicking, so it does not touch the bundle-weight metric that §4.3
is about.

**Accepted losing.** This generator is not byte-reproducible, unlike the seeded
scribble and tile scripts: the capture is real time and a video encoder's rate
control varies run to run. Regenerating churns the file, so it is regenerated
when the design changes, not routinely. It also needs Playwright's browser
installed (`npm run test:e2e:install`), which CI already does.

**Watch for.** A placeholder that looks like a product is how a placeholder gets
shipped. This one says `PLACEHOLDER — NO FILM UPLOADED YET` across the top of
every frame, in the accent colour, for exactly that reason.

## Alternatives

- **Keep `PlaceholderReel` and leave the transport disabled.** Rejected: it left
  the funnel's most intricate component untested and unusable, and the two bugs
  above would still be there on the day the real cut landed — discovered by a
  visitor rather than by CI.
- **Add ffmpeg, or a wasm H.264 encoder.** Rejected: a new dependency, and an
  unnecessary one when a working encoder is already installed.
- **Commit a stock or AI-generated clip.** Rejected on ADR 0003's reasoning,
  unchanged: it would publish someone else's work and make a licensing question
  out of a placeholder.
- **Upload the stand-in to R2 at the real key.** Rejected: `vsl/main.mp4` is the
  owner's slot, and filling it would make "has the film been uploaded yet?"
  unanswerable.
